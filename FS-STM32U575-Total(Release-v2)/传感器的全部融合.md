## 二、架构：数据流

```
硬件 GPIO/I2C
    ↓
BSP 驱动层 (bsp_xxx.c)
    ↓
Model::tick() 周期读取 (Model.cpp)
    ↓
ModelListener 虚函数回调 (ModelListener.hpp)
    ↓
Presenter 转发 (SensorPagePresenter.cpp)
    ↓
View 更新界面 (SensorPageView.cpp)
```

### 新增 ModelListener 回调

在 `ModelListener.hpp` 中新增：

```cpp
virtual void updateBuzzerStatus(bool alarmOn) {}
virtual void updateSmokeStatus(bool alarmOn) {}
virtual void updateAlcoholStatus(bool alarmOn) {}
```

### Model.cpp 传感器读取代码

MQ-2/MQ-3 读取逻辑在 `Model::tick()` 的 `if(gTaskEnMark.UPDATE_APP_TASK_EN)` 块内：

```cpp
// MQ-2 烟雾传感器
static uint8_t lastSmoke = 1;
uint8_t smokeVal = BSP_MQ2_Read();
if (smokeVal != lastSmoke) {
    modelListener->updateSmokeStatus(smokeVal == 0);
    lastSmoke = smokeVal;
}

// MQ-3 酒精传感器
static uint8_t lastAlcohol = 1;
uint8_t alcoholVal = BSP_MQ3_Read();
if (alcoholVal != lastAlcohol) {
    modelListener->updateAlcoholStatus(alcoholVal == 0);
    lastAlcohol = alcoholVal;
}
```

## 四、遇到的问题与解决方案

### 问题 1：printf 转义字符损坏

**现象**：编译报 19 个错误，Model.cpp 第 143-145 行 printf 的引号和换行符变成字面量反斜杠。

**原因**：Edit 工具替换时把 `\r\n` 写成了 `\\r\\n`，把 `"` 写成了 `\"`。

**解决**：用 Python 脚本逐行替换修复。

**正确代码**：
```cpp
printf("[MQ] Smoke(PB8)=%s  Alcohol(PB9)=%s\r\n",
    smokeVal ? "HIGH(Normal)" : "LOW(Alarm!)",
    alcoholVal ? "HIGH(Normal)" : "LOW(Alarm!)");
```

### 问题 2：MQ 调试信息不输出

**现象**：串口只有 `[Model] First tick OK`，没有 `[MQ-DBG]` 输出。

**原因**：MQ 读取代码在 `if(gTaskEnMark.UPDATE_APP_TASK_EN)` 条件内，只有进入 SensorPage 才使能该标志。

**解决**：在 `Model::tick()` 开头新增独立的 MQ 调试块，**不依赖任何页面使能**，直接读 GPIO 寄存器：

```cpp
// MQ-2/MQ-3 调试：直接读GPIO寄存器，每60 tick打印一次
{
    static uint16_t mqDbgCnt = 0;
    if (++mqDbgCnt >= 60) {
        mqDbgCnt = 0;
        uint32_t moder = GPIOB->MODER;
        uint32_t pb9_mode  = (moder >> 18) & 3;
        uint32_t pb8_mode  = (moder >> 16) & 3;
        uint8_t s_hal = (HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_8) == GPIO_PIN_RESET) ? 0 : 1;
        uint8_t a_hal = (HAL_GPIO_ReadPin(GPIOB, GPIO_PIN_9) == GPIO_PIN_RESET) ? 0 : 1;
        printf("[MQ-DBG] PB8 mod=%lu val=%d  PB9 mod=%lu val=%d\r\n",
            pb8_mode, s_hal, pb9_mode, a_hal);
    }
}
```

### 问题 3：MQ-3 不检测酒精（始终 HIGH）

**现象**：酒精靠近传感器，串口始终显示 `Alcohol(PB9)=HIGH(Normal)`。

**排查步骤**：

| 步骤 | 操作 | 结果 |
|------|------|------|
| 1 | 等待预热 2-3 分钟 | 无效 |
| 2 | 逆时针调整灵敏度电位器 | 无效 |
| 3 | 用杜邦线短接 PB9 到 GND | **仍然 HIGH** |
| 4 | 读取 GPIOB->MODER 寄存器 | mod=0 (输入模式) 正确 |
| 5 | 读取 GPIOB->PUPDR 寄存器 | pupd=1 (上拉) 正确 |
| 6 | BSP 和 HAL 读取值对比 | 两者一致，代码正确 |
| 7 | PB8 短接 GND 测试 | 正常变 LOW |

**结论**：PB9 引脚硬件异常（疑似损坏或虚焊）。配置正确、代码正确，但引脚物理上不响应电平变化。

**临时方案**：可以考虑换到 PB11 或 PB12 空闲引脚，修改 `bsp_mq3.h` 中的 `MQ3_GPIO_PIN` 定义，并在 CubeMX 中配置对应引脚。

### 问题 4：CubeMX Generate Code 清空初始化代码

**现象**：在 CubeMX 中配置 PB9 后 Generate Code，烧录后屏幕黑屏只有背光，串口只有 `[Model] Constructor OK`。

**原因**：CubeMX 在 `USER CODE BEGIN 2` 和 `USER CODE END 2` 之间生成了空白行，**删除了所有初始化代码**：传感器初始化、NFC、显示屏、触摸屏、PWM 背光、ESP8266、ADC 校准等全部丢失。

**解决**：从 git diff 恢复 USER CODE BEGIN 2 的内容：

```c
/* USER CODE BEGIN 2 */
for(gTaskIndex = 0;gTaskIndex < OS_TASKLISTCNT;gTaskIndex++)

// NOR Flash初始化
OSPI_W25Qxx_Init();

// 传感器初始化
BSP_MQ2_Init();
BSP_MQ3_Init();
BSP_MOTOR_Init();
// NFC
NFC_Init(&nfc, &huart4, &huart1, nfc_rx_pool, NFC_BUF_SIZE);
// PWM背光
HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_3);
__HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_3, 0);
gBacklightVal = 90;
Update_Backlight(90);
// 显示屏+触摸
ILI9341_Init();
FT6336_init();
// 传感器
mpu_init_dmp();
ap3216c_init();
SCD41_Init();
ESP8266_Init(&huart5, (uint8_t *)gRX3_BufF, 115200);

// ADC
```

## 五、蜂鸣器 GPIO 冲突解决

### 问题

TouchGFX 弹窗中开启蜂鸣器后，主循环定时器回调每 150ms 会把 PA15 复位，导致蜂鸣器只响一瞬间。

### 解决方案

新增全局标志位 `gBuzzerModalActive`，主循环检查标志决定是否复位蜂鸣器：

```c
// main.c: PV 区
volatile uint8_t gBuzzerModalActive = 0; // 1=TouchGFX占用蜂鸣器

// main.c: 定时器回调中
else if (!gBuzzerModalActive)
{
    HAL_GPIO_WritePin(RUN_BEEP_GPIO_Port, RUN_BEEP_Pin, GPIO_PIN_RESET);
}
```

```cpp
// Model.cpp: TouchGFX 控制时不释放
void Model::setBuzzerOn(bool on)
{
    gBuzzerModalActive = on ? 1 : 0;
    if (on) BEEP_ENABLE();
    else    BEEP_DISABLE();
}
```

## 六、CubeMX Generate Code 后的操作清单

每次在 CubeMX 中修改引脚配置并 Generate Code 后，必须：

1. **检查 `main.c` USER CODE BEGIN 2** 是否被清空，如丢失则从 git 恢复
2. **运行 `fix_after_designer.py`** 修复 Designer 生成的代码问题
3. **检查 `gBuzzerModalActive`** 是否还在 USER CODE BEGIN PV 中
4. **检查 `else if (!gBuzzerModalActive)`** 是否还在定时器回调中
5. 重新编译

## 七、调试串口命令速查

| 输出 | 含义 |
|------|------|
| `[Model] Constructor OK` | Model 构造完成 |
| `[Model] First tick OK` | 第一个 tick 正常（TouchGFX 运行中） |
| `[MQ3] Init done: PB9 MODE=...` | MQ-3 GPIO 初始化完成（启动时） |
| `[MQ-DBG] PB8 mod=... val=... PB9 mod=... val=...` | 每秒一次，MQ 传感器实时状态 |
| `[MQ] Smoke(PB8)=... Alcohol(PB9)=...` | 同上，SensorPage 内每秒一次 |

MODER 值：0=输入, 1=输出, 2=复用功能, 3=模拟（默认）

## 八、MQ 传感器硬件调试

1. **预热**：上电后需要 2-3 分钟预热
2. **灵敏度**：模块上蓝色电位器逆时针调低阈值（更灵敏）
3. **测试 GPIO**：用杜邦线短接传感器 DOUT 引脚到 GND，串口应显示 LOW/0
4. **引脚确认**：MQ-2=PB8, MQ-3=PB9, VCC=3.3V, GND=GND
5. **模块指示灯**：模块上电源 LED 必须亮
