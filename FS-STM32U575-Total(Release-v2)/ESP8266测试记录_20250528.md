```c
void simulate_sensor_data(void)
{
    // 读取传感器
    BSP_SHT20_GetData();
    SCD41_GetData();

    // SHT20 温湿度
    if(gTemRH_Val.Tem > 0.1f && gTemRH_Val.Tem < 100.0f) {
        car_temp = (int)(gTemRH_Val.Tem * 10);
        car_humidity = (int)gTemRH_Val.Hum;
    }

    // MAX30102 心率
    if(n_heart_rate > 0 && n_heart_rate < 300) {
        heart_rate = n_heart_rate;
    }

    // MQ-3 酒精检测（0=报警）
    if(BSP_MQ3_Read() == 0) {
        alcohol = 15;  // 0.15mg/L
        fatigue = true;
    } else {
        alcohol = 0;
    }

    // MQ-2 烟雾检测（0=报警）
    if(BSP_MQ2_Read() == 0) {
        smoke = 50;   // 5.0% LEL
    } else {
        smoke = 5;
    }

    // SCD41 CO2
    co2 = (int)gSCD41_Val.CO2;
    if(co2 < 400) co2 = 400;
    if(co2 > 5000) co2 = 5000;
}
```

## 三、关键问题：HAL_GetTick() 溢出

### 3.1 问题现象
程序运行约 49 天后（或短时间内溢出），卡在 `OneNet_Report_Task()` 的某个阶段：
```
[OneNet] Stage=1, tick=2, next=3874
[OneNet] Stage=1, tick=4294967295, next=3874
```

### 3.2 问题根因
`HAL_GetTick()` 返回 `uint32_t`，当 `now < gOneNet_NextActionTime` 时：
```c
if(now - gOneNet_NextActionTime >= 0)   // uint32_t 减法下溢！
```
例如：`2 - 3874 = 4294966522`（变成超大正数），导致条件永远成立。

### 3.3 解决方案
**使用有符号整数转换处理溢出：**
```c
int32_t timediff = (int32_t)(now - gOneNet_NextActionTime);
if(gOneNet_InitStage == 0 && timediff >= 0) {
    // 执行阶段逻辑
}
```

**原理**：`(int32_t)(2 - 3874) = -3872`，负数条件不成立，逻辑正确。

### 3.4 修复后的非阻塞任务代码
```c
void OneNet_Report_Task(void)
{
    uint32_t now = HAL_GetTick();
    char payload[512];
    int32_t timediff;

    // 阶段0: 测试AT
    timediff = (int32_t)(now - gOneNet_NextActionTime);
    if(gOneNet_InitStage == 0 && timediff >= 0) {
        ESP8266_USART("AT\r\n");
        gOneNet_InitStage = 1;
        gOneNet_NextActionTime = now + 1000;
        return;
    }

    // 阶段1: 设置STA模式
    timediff = (int32_t)(now - gOneNet_NextActionTime);
    if(gOneNet_InitStage == 1 && timediff >= 0) {
        ESP8266_USART("AT+CWMODE=1\r\n");
        gOneNet_InitStage = 2;
        gOneNet_NextActionTime = now + 1500;
        return;
    }

    // 阶段2: 连接WiFi
    timediff = (int32_t)(now - gOneNet_NextActionTime);
    if(gOneNet_InitStage == 2 && timediff >= 0) {
        char cmd[128];
        sprintf(cmd, "AT+CWJAP=\"%s\",\"%s\"\r\n", User_ESP8266_SSID, User_ESP8266_PWD);
        ESP8266_USART("%s", cmd);
        gOneNet_InitStage = 3;
        gOneNet_NextActionTime = now + 8000;  // 等8秒
        return;
    }

    // 阶段3: 配置MQTT
    timediff = (int32_t)(now - gOneNet_NextActionTime);
    if(gOneNet_InitStage == 3 && timediff >= 0) {
        ESP8266_USART("AT+MQTTCLEAN=0\r\n");
        HAL_Delay(100);
        char cmd[512];
        sprintf(cmd, "AT+MQTTUSERCFG=0,1,\"%s\",\"%s\",\"%s\",0,0,\"\"\r\n",
                ONENET_CLIENT_ID, ONENET_PRODUCT_ID, ONENET_TOKEN);
        ESP8266_USART("%s", cmd);
        gOneNet_InitStage = 4;
        gOneNet_NextActionTime = now + 2000;
        return;
    }

    // 阶段4: 连接OneNet
    timediff = (int32_t)(now - gOneNet_NextActionTime);
    if(gOneNet_InitStage == 4 && timediff >= 0) {
        char cmd[128];
        sprintf(cmd, "AT+MQTTCONN=0,\"%s\",%d,1\r\n", 
                ONENET_SERVER_IP, ONENET_SERVER_PORT);
        ESP8266_USART("%s", cmd);
        gOneNet_InitStage = 5;
        gOneNet_Connected = 1;
        gOneNet_LastReportTime = now;
        return;
    }

    // 阶段5: 已连接，定期上报
    if(gOneNet_InitStage == 5 && gOneNet_Connected) {
        timediff = (int32_t)(now - gOneNet_LastReportTime);
        if(timediff >= 10000) {  // 10秒上报
            gOneNet_LastReportTime = now;
            simulate_sensor_data();
            build_onenet_payload(payload, sizeof(payload));

            char cmd[256];
            int len = strlen(payload);
            sprintf(cmd, "AT+MQTTPUBRAW=0,\"%s\",%d,0,0\r\n", 
                    ONENET_TOPIC_PROP_POST, len);
            ESP8266_USART("%s", cmd);
            HAL_Delay(800);
            ESP8266_USART("%s", payload);
        }
    }
}
```

## 七、注意事项

1. **阻塞 vs 非阻塞**: 旧代码 `OneNet_Report_Process()` 是阻塞的，会卡住整个系统。必须使用 `OneNet_Report_Task()` 非阻塞版本。

2. **传感器依赖**: 确保在 `user_app.c` 或其他地方正确初始化 I2C 和传感器。

3. **HAL_Delay 慎用**: 主循环中只能用短延时（<100ms），长延时会阻塞 TouchGFX。

4. **数据类型**: OneNet 物模型定义的数据类型（int/float）必须与 JSON 中的值类型匹配。

## 九、问题排查：卡在 [Model] Constructor OK

### 9.1 问题现象
程序启动后输出：
```
W25Q128 OK,flash ID:EF4018
[MQ3] Init done: PB9 MODE=0 PUPD=1 IDR=0x000003F0
[SCD41] Init failed (sensor not found)
[INIT] ESP8266_Init done
[TEST] Starting OneNet Non-blocking...
[OneNet] Starting non-blocking init...
[INIT] All init done, entering main loop
[Model] Constructor OK   <-- 卡在这里
```

### 9.2 可能原因分析

#### 原因1：TouchGFX Task 阻塞
Model 构造函数执行后，TouchGFX 进入 `MX_TouchGFX_Process()`，可能原因：
- **RTOS 任务栈溢出**：TouchGFX 任务的栈空间不足
- **任务优先级问题**：TouchGFX 任务优先级过高，饿死其他任务
- **OSSemaphore 死锁**：Model 中使用了信号量但未正确释放

**解决方案**：
```c
// 在 freertos.c 中检查 TouchGFX 任务栈大小
#define TOUCHGFX_TASK_STACK_SIZE  4096  // 至少 4KB

// 降低 TouchGFX 任务优先级（低于 MQTT 任务）
osThreadDef(touchGFXTask, TouchGFX_Task, osPriorityBelowNormal, 0, 4096);
```

#### 原因2：OneNet_Report_Task() 在主循环中阻塞
虽然名为非阻塞，但如果 `OneNet_Report_Task()` 内部有长的 `HAL_Delay`，会阻塞整个主循环。

**检查点**：
```c
// 在 OneNet_Report_Task() 中避免使用 HAL_Delay
// 阶段3中的 HAL_Delay(100) 需要替换为无阻塞延时

// 错误：
HAL_Delay(100);  // 会阻塞整个系统

// 正确：拆分为多个阶段或使用非阻塞延时
if (now - gOneNet_LastDelayTime >= 100) {
    // 执行下一步
}
```

#### 原因3：UART 中断/缓冲区问题
ESP8266 使用 UART，如果：
- 中断未使能
- DMA 缓冲区配置错误
- UART 接收阻塞

会导致 `ESP8266_USART()` 函数阻塞。

**检查 UART 配置**：
```c
// 在 bsp_esp8266.c 中检查
// 1. UART 中断优先级是否正确
HAL_NVIC_SetPriority(USART5_IRQn, 5, 0);  // 优先级不能太低

// 2. 确保中断已使能
__HAL_UART_ENABLE_IT(&huart5, UART_IT_RXNE);
```

#### 原因4：Flash/FS 初始化阻塞
你的项目使用了 W25Q128 Flash，如果：
- 文件系统挂载阻塞
- TouchGFX 从 Flash 加载资源失败

**检查点**：
```c
// 检查 TouchGFXHAL.cpp 中的 blockCopy() 函数
// 如果从 Flash 读取数据阻塞，会导致画面刷新卡住
```

### 9.3 调试建议

1. **添加更多调试输出** 到关键位置：
```c

while (1) {
    printf("[Main] Before TouchGFX_Process\n");
```

### 9.4 推荐的修复代码

如果问题是 OneNet 任务中的 `HAL_Delay` 导致，可以这样修复：

```c
// 阶段3: 配置MQTT - 移除阻塞延时
if(gOneNet_InitStage == 3 && timediff >= 0) {
    static uint8_t mqtt_substage = 0;
    static uint32_t mqtt_delay_start = 0;

        case 1:

                    ONENET_CLIENT_ID, ONENET_PRODUCT_ID, ONENET_TOKEN);
            ESP8266_USART("%s", cmd);
            gOneNet_InitStage = 4;
            gOneNet_NextActionTime = now + 2000;
            mqtt_substage = 0;  // 重置子阶段
            return;
    }
}
```

## 十、ESP8266 → ESP32 迁移指南

如果你需要将代码从 ESP8266 (AT 指令模式) 迁移到 ESP32 (WROOM/WROVER)，主要区别如下：

### 10.1 架构差异

| 特性 | ESP8266 (AT 固件) | ESP32 (直连) |
|------|-------------------|--------------|
| 通信方式 | UART AT 指令 | SPI/UART 或板载集成 |
| 连接位置 | 外部模块 | 集成在同一 PCB |
| MQTT 库 | 通过 AT 指令 | ESP-IDF 原生 MQTT |
| 是否需要 MCU | 需要 (STM32) | ESP32 本身就是 MCU |

### 10.2 如果你保留 STM32 + ESP32 组合

ESP32 作为 WiFi 协处理器（类似 ESP8266 的用法）：

```c
// esp32_at.h - 与 ESP8266 类似，但 AT 指令略有不同
#define ESP32_USART(fmt, ...)  HAL_UART_Transmit(&huart5, (uint8_t*)fmt, ##__VA_ARGS__)

// ESP32 AT 指令差异
// ESP8266: AT+CWMODE=1
// ESP32: AT+CWMODE=1 (相同)

// ESP8266: AT+CWJAP="SSID","PWD"
// ESP32: AT+CWJAP="SSID","PWD" (相同)

// MQTT 指令差异较大 - ESP32 使用 AT+MQTT 指令集
```

### 10.3 如果你直接用 ESP32 做主控（替代 STM32）

需要重构整个项目：
1. 移植 TouchGFX 到 ESP32
2. 直接在 ESP32 上读取传感器
3. 使用 ESP-IDF 的 MQTT 客户端库

### 10.4 ESP32 AT 固件 MQTT 示例

```c
// bsp_esp32.c
#include "bsp_esp32.h"

// ESP32 AT 指令与 ESP8266 差异
void ESP32_MQTT_Init(void)
{
    // ESP32 需要先使能 MQTT 功能
    ESP32_USART("AT+MQTTUSERCFG=0,1,\"client\",\"user\",\"pass\",0,0,\"\"\r\n");
    HAL_Delay(100);
    
    // 连接 MQTT 服务器
    ESP32_USART("AT+MQTTCONN=0,\"broker.emqx.io\",1883,1\r\n");
    HAL_Delay(2000);
}

void ESP32_MQTT_Publish(const char* topic, const char* payload)
{
    char cmd[256];
    int len = strlen(payload);
    // ESP32 使用 AT+MQTTPUBRAW (与 ESP8266 相同)
    sprintf(cmd, "AT+MQTTPUBRAW=0,\"%s\",%d,0,0\r\n", topic, len);
    ESP32_USART("%s", cmd);
    HAL_Delay(500);
    ESP32_USART("%s", payload);
}
```

### 10.5 ESP32 与 ESP8266 AT 指令对照表

| 功能 | ESP8266 | ESP32 |
|------|---------|-------|
| 测试 AT | `AT` | `AT` |
| 设置 STA | `AT+CWMODE=1` | `AT+CWMODE=1` |
| 连接 WiFi | `AT+CWJAP` | `AT+CWJAP` |
| 查询 IP | `AT+CIFSR` | `AT+CIFSR` |
| MQTT 配置 | `AT+MQTTUSERCFG` | `AT+MQTTUSERCFG` (相同) |
| MQTT 连接 | `AT+MQTTCONN` | `AT+MQTTCONN` (相同) |
| MQTT 发布 | `AT+MQTTPUBRAW` | `AT+MQTTPUBRAW` (相同) |
| MQTT 订阅 | `AT+MQTTSUB` | `AT+MQTTSUB` (相同) |

**结论**：ESP32 的 AT 固件与 ESP8266 几乎相同，代码迁移只需修改串口初始化和宏定义。

## 十一、根本原因总结：卡在 [Model] Constructor OK

### 问题根因
经过实际排查，此问题**并非 OneNet MQTT 导致**，而是 **TouchGFX Designer 代码生成 Bug**。

每次在 TouchGFX Designer 中点击 "Generate Code" 后，Designer 会重新生成 `TouchGFX/generated/` 目录下的代码，但 Designer 本身有已知 Bug：
1. SwipeContainer 尺寸丢失（变成 0x0）→ 导致黑屏
2. WiFiModalLink Z 层级错误 → 被遮挡
3. 其他界面组件问题

### 正确工作流程
```
□ 1. 在 TouchGFX Designer 中修改界面
    ↓
□ 2. 点击 "Generate Code" (或按 F5)
    ↓  【关键！这一步会引入 Bug】
□ 3. 【必须】运行修复脚本：
    cd TouchGFX
    python fix_after_designer.py
    ↓
□ 4. 回到 STM32CubeIDE 编译 & 烧录
```

### 遗忘脚本的后果
如果忘记运行 `fix_after_designer.py`：
- 屏幕黑屏/不亮
- Model 构造函数执行后卡住（`[Model] Constructor OK` 后无输出）
- 看起来像程序死机，实则是 TouchGFX 渲染异常
